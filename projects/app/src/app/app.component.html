Limitação: po-number usa <input type="number"> nativo do browser. O browser REMOVE zeros à esquerda automaticamente. Não há como exibir "000.1" num input number.

p-mask no po-number: A propriedade é EXPLICITAMENTE desabilitada (override para string vazia). A documentação diz: "incompatível com po-number".

Capacidade: po-decimal usa <input type="text"> com formatação própria. Suporta separador de milhar e casas decimais FIXAS (p-decimals-length).

Limitação: NÃO suporta zeros à esquerda na parte inteira. A formatação é exclusivamente: separador de milhar + casas decimais fixas após separador decimal.

Capacidade: PoMask suporta máscara posicional: cada '9' = aceita dígito 0-9. Caracteres fixos (., -, /) são inseridos automaticamente.

Limitação: A máscara é POSICIONAL e requer que o usuário preencha TODOS os caracteres. Se a máscara é "999.9", o usuário precisa digitar 4 dígitos. Não há preenchimento automático com zeros à esquerda. O model resultante é STRING, não número.

Problema central: Se o usuário digita apenas "1", a máscara exibe "1" sem completar com zeros. Não existe lógica de "pad left" (zeros à esquerda) no PoMask.

Formato ABL requerido: >9,99,99,99 / >>>,>>>,>>9.99 / 999.9

Comportamento esperado: Entrada = 1, Saída formatada = 000.1 (zeros à esquerda preenchidos automaticamente)

  • po-number: Usa input type=number. Browser remove zeros à esquerda. Máscara desabilitada. Impossível sem refatoração.
  • po-decimal: Usa input type=text, mas a formatação é fixa (milhar + decimais). Não interpreta format strings ABL. Não faz pad-left com zeros.
  • po-input + PoMask: Suporta máscara posicional, mas exige preenchimento completo pelo usuário. Sem auto-fill de zeros. Model é string.

Gaps para implementar a demanda:

  1. Nenhum componente interpreta format strings no padrão ABL (>, <, Z, 9, etc.)
  2. Nenhum componente faz "pad left" automático com zeros na parte inteira
  3. po-number não pode exibir zeros à esquerda por limitação do input type=number
  4. po-decimal não tem propriedade para definir largura fixa da parte inteira
  5. PoMask não tem conceito de "preenchimento automático a partir da direita"
  6. Separadores customizados por posição (ex: 99,999,9,99.9999) não são suportados
